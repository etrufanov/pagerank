## Что такое PageRank и зачем он нужен

PageRank — мера "важности" вершины в ориентированном графе. Изначально придуман в Google для ранжирования веб-страниц: страница тем важнее, чем больше на нее ссылается важных страниц. Важность распределяется по исходящим ссылкам: страница с рангом `r` и `k` исходящими ссылками передает по каждой ссылке `r/k`.

Формально PageRank — это стационарное распределение случайного блуждания по графу с телепортацией. Гуляющий с вероятностью `d` (damping, обычно `0.85`) переходит по случайной исходящей ссылке, а с вероятностью `1-d` "телепортируется" в случайную вершину. Ранг вершины `v` на каждой итерации:

```
rank[v] = (1-d)/N + d * (dangling_mass/N + sum_u { rank[u]/outdeg[u] })
                                           сумма по всем u, ссылающимся на v
```

- `N` — число вершин, `d` — damping-фактор.
- `(1-d)/N` — вклад телепортации (каждая вершина получает поровну).
- `dangling_mass` — суммарный ранг вершин без исходящих ребер. Их массу некуда передать по ссылкам, поэтому она равномерно перераспределяется на все вершины — иначе суммарный ранг "утекал" бы с каждой итерацией.
- Сумма всех рангов всегда примерно равна `1.0`.

Где применяется помимо веб-поиска: ранжирование узлов в социальных сетях, анализ цитирования научных статей, рекомендательные системы, выявление ключевых дорог в транспортных сетях, приоритизация в графах зависимостей — везде, где важность узла определяется важностью ссылающихся на него узлов.

## Как мы храним данные и считаем метрику

### Pull-модель и CSR

Мы храним граф как входящие ребра, сгруппированные по вершине-назначению (CSR — compressed sparse row). Для каждой вершины `v` все ссылающиеся на нее вершины лежат подряд:

```
sources: [ ..., u_v1, u_v2, ..., u_vk, ... ]
offsets:        ↑ offsets[v]        ↑ offsets[v+1]
```

`sources[offsets[v]..offsets[v+1]]` — список источников входящих в `v` ребер.

Это дает pull-модель: на каждой итерации поток, считающий ранг вершины `v`, читает общий вектор `rank[]` и пишет только в свою ячейку `next[v]` (обновленное значение метрики). Потоки делят диапазон вершин на непересекающиеся куски, отсюда получается параллелизм.

Почему pull, а не push? В push-модели (группировка по источнику) поток, обрабатывая ребро `u -> v`, должен добавить вклад в `next[v]`, а в `v` могут писать сразу несколько потоков, возникает race condition. Pull избавляет от этого ценой того, что граф хранится как входящие ребра. Так как вектор рангов помещается в RAM, читать его из всех потоков дешево.

### Построение графа: counting sort в два прохода

1. Проход 1 (подсчет). Читаем входной файл с ребрами и считаем входящую и исходящую степень каждой вершины. По входящим степеням строим `offsets` (префиксная сумма).
2. Проход 2 (размещение). Читаем входной файл с ребрами и для каждого ребра `(u, v)` записываем источник `u` в следующий свободный слот назначения `v` (`cursor[v]`). Так все источники группируются по назначению.

Входной файл никогда не загружается в память целиком, оба прохода потоковые. В RAM
живут только массивы размера `N` (кол-во вершин).

## Вычислительная сложность и точность

Пусть `N` — число вершин, `E` — число ребер, `k` — число итераций до сходимости.

**Время:**

- Построение графа — `O(E)`: два потоковых прохода по CSV + `O(N)` на префиксную сумму.
- Одна итерация — `O(N + E)`: каждая вершина суммирует вклады своих входящих ребер (в сумме по всем вершинам — это `E`) + `O(N)` на подсчет dangling-массы и L1-нормы. Все три прохода параллелятся по вершинам.
- Итого — `O(E + k(N + E))`. На практике `k = 50–100`.

**Память:**

- RAM — `O(N)`: несколько массивов на вершину. От числа ребер не зависит.
- Диск — `O(E)`: `4E` байт под `sources`.

**Точность:**

- Все вычисления во float64.
- PageRank сходится геометрически со скоростью `d`: ошибка после `k` итераций = `d^k`. Для `d = 0.85` и `eps = 1e-6` достаточно порядка `ln(eps)/ln(d) = 85` итераций, отсюда дефолт `max_iter = 100`.
- Критерий остановки — L1-норма разности векторов между итерациями (`sum_v { |next[v] - rank[v]| } < eps`). При недостижении сходимости за `max_iter` программа выдает предупреждение и возвращает последнее приближение.
- Из-за параллельного суммирования порядок сложений float64 не фиксирован, поэтому результаты могут отличаться на величину машинной погрешности от запуска к запуску. На ранжирование вершин это не влияет.

## Запуск

Программа собирается в один статический бинарник без внешних зависимостей рантайма.

Нужен установленный Rust: https://rust-lang.org/tools/install. Если его нет:

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### Вариант 1. Сборка из исходников

Сборка и запуск:

```sh
# Релизная сборка (с оптимизациями)
cargo build --release

# Бинарник появится здесь:
./target/release/pagerank edges.csv -o page_rank.csv
```

### Вариант 2. Установка в PATH

```sh
cargo install --path .
pagerank edges.csv -o page_rank.csv
```

### Опции командной строки

| Опция | По умолчанию | Описание |
|---|---|---|
| `[INPUT]` | `edges.csv` | Входной CSV со списком ребер |
| `-o, --output <FILE>` | `page_rank.csv` | Выходной CSV с рангами |
| `--num-threads <N>` | число логических ядер | Количество потоков |
| `--max-iter <N>` | `100` | Максимум итераций |
| `--damping <F>` | `0.85` | Damping-фактор `d` |
| `--eps <F>` | `1e-6` | Порог сходимости (L1-норма) |
| `-v` / `-vv` | info | Подробность логов (`-v`: debug, `-vv`: trace) |
| `-q` | - | Тише (warn / error) |
| `--help` | - | Полная справка |

## Форматы данных

Вход: CSV с обязательным заголовком `from,to`, по одному ребру на строку; id вершин — целые числа (`i32`):

```csv
from,to
1,2
2,3
3,1
```

Выход — CSV с заголовком `vertex,rank`: исходный id вершины и ее ранг:

```csv
vertex,rank
1,0.3333333333333333
2,0.3333333333333333
3,0.3333333333333333
```
